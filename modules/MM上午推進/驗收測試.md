# MM 上午推進等效驗收案例

## 驗收原則

精簡提示詞必須在下列情境中，維持與原完整提示詞相同的行為邊界、失敗標記與輸出順序。

## 正常情境

1. GitHub 可讀、昨晚 Markdown 存在、Airtable 尚無相同卡：應選出至多一項最小行動並建立新卡。
2. GitHub 可讀、昨晚 Markdown 存在、Airtable 已有相同卡：應更新既有卡，不得建立第二張。
3. 昨晚有多個未承接事項：應只選至多一項最小行動。
4. 所有候選事項都已由專用單位承接：應回報沒有額外任務，不得湊數。

## GitHub 異常

5. 無法確認 `main` 最新 commit：標記「MM 治理規範未完成校正」並停止執行性建議。
6. 必要治理文件缺失：同上。
7. 規則互相衝突：停止採用衝突規則並回報，不得自行補完。

## 回顧異常

8. 找不到昨晚 Markdown：標記「昨晚 MM 回顧正式檔未找到」。
9. 只有同日 Google 文件副本：不得把副本當成 Markdown 正式主版本。
10. 只找到前天回顧：不得冒充昨晚回顧。
11. Slack 有舊回顧訊息但 Drive 無正式檔：不得以 Slack 替代。

## 任務歸屬

12. 昨晚只有求職事項：標記已交由「台中流程職缺精選」，不得建立上午主卡。
13. 同時有求職與非求職事項：略過求職事項，繼續評估非求職事項。
14. 某事項已由專用 AI 或專用專案承接：不得重複執行或建立為上午主卡。

## Airtable 異常

15. 找不到 Base、資料表或欄位：標記「今日最小行動任務卡未完成建立」並說明位置。
16. 建立或更新失敗：同上，不得宣稱成功。
17. 無法確認是否已有相同卡：不得直接新增可能重複的第二張卡。
18. 工具可用但沒有可驗證寫入結果：不得宣稱成功。

## AI 新聞

19. 昨日只有兩則真正重要消息：只列兩則，不得湊滿三則。
20. 搜尋結果混有前幾日舊聞：必須排除。
21. 新聞發布日期無法確認：不得納入。
22. 上午推進尚未完成：不得先輸出 AI 科技摘要取代主流程。

## 通過標準

每個案例都必須符合：

- 正確讀取順序
- 正確任務歸屬
- 至多一項最小行動
- Airtable 先查重再寫入
- 外部操作只有可驗證結果才算成功
- 異常標記文字正確
- 上午推進在前，AI 科技摘要在後

## 驗收紀錄

| 測試範圍 | 狀態 |
|---|---|
| 條款靜態對照 | 通過 |
| 路徑與內部引用 | 通過 |
| 情境行為驗收 | 待執行 |
| 正式排程實跑 | 未開始 |

全部必要案例通過後，精簡提示詞才可進入正式排程替換審查。
