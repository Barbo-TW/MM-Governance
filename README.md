# MM Governance

MM Governance 是 MM 提供給參與工作的 AI 使用的公開治理規範入口。

## 閱讀順序

任何參與 MM 對話或工作的 AI，開始前應依序閱讀：

1. [`README.md`](README.md)
2. [`AGENTS.md`](AGENTS.md)
3. 若任務涉及聊天歸檔，再閱讀 [`AI共同聊天規範.md`](AI共同聊天規範.md)
4. 若任務涉及分流，再閱讀 [`MM分流規範.md`](MM分流規範.md)

若無法讀取上述任務適用文件、無法確認版本，或文件內容互相衝突，應先向使用者說明，不得自行補完規則。

## 權威與同步模型

```text
GitHub main（公開共通治理來源）
→ commit 與版本回讀驗證
→ 本機唯讀同步公開治理白名單
→ 雲端與本機 AI 工作前閱讀任務適用規範
```

- 本 Repository `main` 分支是公開、跨 AI 共通治理的來源。
- 本機以唯讀方式同步公開治理白名單到獨立鏡像；不得直接覆蓋本機完整規則、私人狀態或地方規則。
- 新增公開治理文件後，應同步更新本機治理白名單，避免新規範存在 GitHub 卻未進入本機同步範圍。
- 私人 MM（使用者指定的雲端或本地工作區）保存私人狀態、決策、專案內容、索引、實際目的地、主版本與地方限制；這些私人資料不得放入公開 Repository。去個人化的邏輯分類及共通分流判斷規則可在此公開。
- GitHub commit SHA、檔案 SHA-256 與回讀結果可驗證後，才可將該版本視為已同步。
- 公開共通治理與本機私人／地方規則跨界衝突時，停止衝突部分並請使用者確認；不得自行採用較寬鬆版本。

## 公開邊界

本 Repository 只發布去個人化的共通規範，不收錄：

- 個人目前狀態、卡點、提醒與私人決策
- 聊天逐字稿與未公開專案內容
- 本機絕對路徑
- 帳號、Token、Slack 識別資訊或其他敏感資料

## 分流工作入口

先讀 `MM分流規範.md`，再讀當次已授權私人工作區的入口、地方規則、目的地對照、主版本與既有內容。Google Drive 等私人雲端可以承接正式分流，但公開治理不包含私人資料夾 ID，也不代替任務授權。正式分流、本地同步與自動化建置是不同完成條件。
