# MM Governance

MM Governance 是 MM 提供給雲端 AI 與本地 AI 使用的公開治理規範入口。

## 閱讀順序

任何參與 MM 對話或工作的 AI，開始前應依序閱讀：

1. [`README.md`](README.md)
2. [`AGENTS.md`](AGENTS.md)
3. [`生成式AI共同聊天規範.md`](生成式AI共同聊天規範.md)

若無法讀取上述文件、無法確認版本，或文件內容互相衝突，應先向使用者說明，不得自行補完規則。

## 權威與雙端更新模型

```text
雲端 AI ─┐
         ├─ 建立分支、commit 與 Pull Request
本地 AI ─┘
                ↓
        使用者審查與合併
                ↓
      GitHub 預設分支正式版本
                ↓
  雲端 AI 與本地 AI 回讀並同步
```

- 本 Repository 的預設分支是 MM 公開治理規範的正式來源（Single Source of Truth）。
- 雲端 AI 與本地 AI 均可依當次明確授權建立分支、commit 與 Pull Request。
- 未合併的本地檔案、工作分支、commit 或 Pull Request 都屬候選變更，不視為正式治理規範。
- 只有完成使用者審查、合併至預設分支，且可回讀驗證的內容，才視為正式發布。
- 兩端同時修改同一規則時，不得以檔案修改日期直接覆蓋；應透過 Git diff、commit 與 Pull Request 比較差異，由使用者審查後決定合併內容。
- 比較兩端版本時，可用更新時間協助判斷先後，但時間戳不能取代內容差異、來源證據與合併紀錄。
- AI 開始 MM 對話或工作前，應回讀預設分支最新版本，不得以本機快取、聊天記憶或未合併分支冒充正式規範。

## 公開邊界

本 Repository 只發布去個人化的共通規範，不收錄：

- 個人目前狀態、卡點、提醒與私人決策
- 聊天逐字稿與未公開專案內容
- 本機絕對路徑
- 帳號、Token、Slack 識別資訊或其他敏感資料
